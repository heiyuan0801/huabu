# Docker Deployment

Use Docker Compose to run the application from a release image or build it from the current source.

## Use the published image

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
docker compose up -d
```

Open `http://localhost:3000`.

## Build locally

```bash
docker compose up -d --build
```

The default Compose file builds `infinite-canvas:local` from the current `Dockerfile`. It does not pull the published image.

To run the published image directly:

```bash
docker run -d --name infinite-canvas -p 3000:3000 --restart unless-stopped ghcr.io/basketikun/infinite-canvas:latest
```

## Documentation image

The documentation in `docs/` is a separate Next.js standalone application with server capabilities.

```bash
cd docs
docker compose up -d
```

To build it from the current source:

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

The main application container only runs the static frontend. Canvases, My Assets, generation history, and API keys are stored in the browser by default, while prompt repositories are fetched directly by the frontend. No persistent data volume is required for this data.

The main application image uses nginx to serve the Vite frontend and same-origin proxies `/ai-proxy` requests to the default Weilai relay at `https://api1.weilai.chat`. HTTPS deployments also proxy returned generated media through `/media-proxy`; custom AI channels and third-party prompts remain browser-direct.

## Optional analytics

No analytics are enabled by default. A deployment can enable GA4, Baidu Analytics, or both at runtime:

| Variable | Description |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 measurement ID (`G-XXXX`) |
| `ANALYTICS_BAIDU_ID` | Baidu site ID, the hash after `hm.js?` |

```yaml
services:
  app:
    image: infinite-canvas:local
    build: .
    ports:
      - "3000:3000"
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

SPA route changes automatically report page views to enabled providers. Only configure analytics IDs on sites you control, and do not commit them to the repository.
